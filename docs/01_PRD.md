## 1. 业务背景与项目定位

### 1.1 客户与业务对象

**客户：** 县级司法局行政合法性审查部门。

**业务对象（送审单位）：**
- 县政府各部门
- 乡镇人民政府
- 街道办事处
- 公共机构
- 国有单位

**业务对象（送审材料）：**
- 行政规范性文件
- 政策文件
- 制度文件
- 公文材料

### 1.2 现有人工审核流程

| 序号 | 审查项 |
|------|--------|
| 1 | 是否属于行政规范性文件 |
| 2 | 制定主体是否合法 |
| 3 | 是否具有制定权限 |
| 4 | 制定程序是否完整 |
| 5 | 文件内容是否合法 |
| 6 | 是否违反禁止性规定 |
| 7 | 是否损害公民、法人和企业权益 |
| 8 | 是否需要修改 |

### 1.3 项目目标

通过 AI 完成人工审核前置工作，将人工审查时长从平均 3-5 个工作日压缩到 1 个工作日内，AI 初审覆盖率 ≥ 80%，最终人工审查闭环保留。

**关键能力：**
1. 文件解析（OCR + 结构化）
2. 法规检索（多层级法规库）
3. 风险识别（六维审查模型）
4. 审核意见生成（带证据链）
5. 证据引用（条款级原文引用）
6. 人工复核闭环（反馈回流）

### 1.4 项目定位

| 项目 | 是否 | 说明 |
|------|------|------|
| 通用聊天机器人 | ✗ | 不做无边界问答 |
| 政府级 AI 合规审核工作流系统 | ✓ | Graph + Harness + Loop + Evaluation |
| 可商用交付的 Agent 平台 | ✓ | 面向司法局、市监局、发改委等多场景复用 |

### 1.5 合规与责任边界

- AI 不可替代最终法律责任
- 所有 AI 判断必须附法规依据（Evidence Harness 强制约束）
- 最终审查意见书必须由人工签字确认
- 审计日志全链路留存

## 2. 用户角色与典型场景

### 2.1 用户角色矩阵

| 角色 | 单位 | 核心诉求 | 系统权限 |
|------|------|----------|----------|
| 送审人 | 县直部门/乡镇/街道 | 提交材料、查询进度、接收反馈 | 上传/查询本人任务 |
| 审查员 | 司法局合法性审查科 | 复核 AI 意见、最终签发 | 审核任务池/反馈回流 |
| 审查主管 | 司法局合法性审查科负责人 | 任务分派、质量抽检、报告归档 | 全任务/统计/KPI |
| 系统管理员 | 司法局信息中心 | 用户/权限/法规库维护 | 系统管理 |
| 法规库管理员 | 司法局合法性审查科 | 法规更新、案例库维护 | 法规库 CRUD + 评测 |

### 2.2 典型场景

**场景 S-01：日常送审**
1. 送审人上传 Word 版《XX 县关于促进中小企业发展的若干意见》
2. 系统 3 分钟内完成解析 → 检索 → 审核 → 报告
3. 审查员收到 AI 初审意见，复核后签发

**场景 S-02：复杂公文**
1. 送审人上传扫描 PDF（带公章）
2. OCR + 结构化后识别为"规范性文件"
3. 内容审核触发"违法设置行政许可"风险点
4. Verifier Retry Loop 重新检索法规、补全证据
5. 报告输出修改建议，送审人回退修改后重审

**场景 S-03：法规更新回流**
1. 新《行政处罚法》实施
2. 法规库管理员导入新法规
3. 系统自动重跑近 30 天历史案例，标记需复查项

## 8. 附录

### 8.1 术语表

| 术语 | 定义 |
|------|------|
| 行政规范性文件 | 县级以上政府及其部门制定的涉及公民、法人权利义务的具有普遍约束力、可重复适用的文件 |
| Harness | 约束 Agent 行为的工程层（Context/Evidence/Quality/Security 四类） |
| Loop | 自优化机制（审核质量/人工反馈/法规更新 三类） |
| Verifier | 验证 Agent 输出是否合规的守门员 |
| Evidence Chain | 风险判断 → 法规条款 → 原文 → 解释 的证据链 |

- 各省/市/县《行政规范性文件管理办法》
