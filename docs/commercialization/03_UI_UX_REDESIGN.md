# 03 UI/UX 重设计方案（Design System & Page Redesign）

> 前置：已有 [UI_PRODUCT_AUDIT.md](file:///Users/shajindi/traework/legal-review/UI_PRODUCT_AUDIT.md)（UI-M0/M1 已落地：语义色 token、EmptyState/Skeleton/ErrorState、OnboardingDialog 均已就位）
> 本方案只做**商业化导向**的增改，不重做已达标的部分。原则：商业价值 > 视觉；不编造案例；不破坏现有功能。

---

## 1. 设计原则（针对买家画像修正）

买家是**县级司法局公务员**，不是硅谷工程师。三条硬规则：

1. **业务语言替代技术语言**：首页删弱「LangGraph / DeepSeek V4 / BGE-M3」等参数，改为「依据可查、过程留痕、人工复核兜底」等采购决策语言。技术栈收进「技术白皮书」折叠区。
2. **信任层优先于功能层**：竞品研究结论（02 §6.3）——引用溯源是第一信任要素。法规依据卡片从产品深处提到首页第一屏。
3. **合规可见**：ICP/主体/协议入口必须在页脚常态可见（当前为占位文案，等运营方提供正式值后自动生效——机制已建好，勿改）。

## 3. 定价页改造（/pricing）

1. **公开化**：从 `(app)` 受保护组移出为公开路由，游客可见；CTA 未登录 → `/register`，已登录 → 升级流程。**这是漏斗最大堵点。**
2. 信息架构：三卡 + 「推荐」徽标（Pro 高亮已有）+ 周期切换（月/季/年，显示折算月价与节省额）+ 下方对比表（法规库范围/额度/导出/支持）。
3. 删除「线上支付与开票功能正在接入中」横幅；支付宝通道标「支持」，微信通道灰置「即将开通」（与真实状态一致）。
4. 每卡下方加一行信任文案：「支付由支付宝提供 · 支持对公发票」。

## 4. 注册/登录改造

1. 注册表单底部加协议勾选：「我已阅读并同意《用户协议》《隐私政策》」链接到 /terms /privacy（页面已存在），未勾选禁用提交按钮。**个保法合规要求。**
2. 注册成功后直接进入控制台并触发 Onboarding（已有 OnboardingDialog），Onboarding 选择完成后**直接跳上传页**，缩短注册→首任务路径。
3. 移动端表单点击区域 ≥44px（现有达标，回归测试即可）。

## 5. 付费墙与额度体验

| 场景 | 方案 |
| --- | --- |
| 免费额度剩余 | UsageCard 已显示进度；增加「最后 1 次」预警态（amber） |
| 额度用尽（429） | 弹层文案改为价值回顾：「你已完成 2 次完整审查」+ 展示上次报告链接 + 升级按钮直达 /pricing；禁止出现「系统错误」类技术话术 |
| 支付成功 | 回跳后显示成功态 + 立即上传第一个文件 CTA（激活闭环） |
| 支付失败/取消 | 回到 /pricing 并 toast 说明原因与重试入口（后端已有查单补偿，前端态需核对） |

## 6. 设计系统增量（基于现有 token）

- globals.css 语义色/风险色/字体/间距已就位（UI-M0），本轮**不新增 token**，仅补两个组件：
  - `<TrustStrip>`：政策依据+运行指标+合规标识的横条组件（首页/定价页复用）
  - `<UpgradeDialog>`：额度用尽统一升级引导弹层（替换散落的 429 文案）
- 骨架屏/空态/错误态已有，推广到 pricing 与 billing 列表页。
- 品牌色 #7c3aed 保留；政务场景下 Hero 区域维持白底高对比，不引入渐变玻璃拟态。

## 8. 移动端

390×844 实测可浏览可点击（✔）。本轮只做回归验证，不做专项重设计；定价页公开化后需补一次移动端截图回归。

## 9. 不做的事（明确排除）

- 不重做品牌色/Logo/字体体系
- 不加营销型大面积渐变与装饰动画
- 不新增无真实数据的「客户评价」轮播
- 不在未取得微信支付商户资质前启用微信渠道按钮
- 不改动已上线的支付回调、CSP nonce、限流等安全链路

## 10. 验收标准

1. 游客不登录可完整浏览 /pricing 并看到真实价格
2. 首页价格与后端 pricing 接口同源一致；体验版额度文案=累计 2 次
3. 注册必须勾选协议才能提交
4. 首页含政策依据信任条 + FAQ 区块
5. 桌面+移动截图回归无布局破坏，`pnpm build` 通过，CSP 无新增报错
