# 04 产品功能优化与开发路线图（Product Roadmap）

> 判定标准：从「AI 能回答」到「AI 能完成用户任务」——用户任务是「把一份规范性文件的合法性审查初稿做出来并留痕归档」。

---

## 1. 功能价值判定

### 1.1 真价值（继续投入）

| 功能 | 价值证据 | 动作 |
| --- | --- | --- |
| 11 节点审查流水线（SSE） | 主交付物，全流程可追溯 | 保持；把节点进度翻译为业务阶段文案 |
| 条款级法规依据（Evidence Harness） | 政务采购第一信任要素；竞品无此深度 | **强化：首页展示+报告导出内嵌** |
| 审查意见书/报告 | 法定交付物形态 | **补导出**（docx/PDF），这是「留痕归档」任务的最后一公里 |
| 历史记录 | 复用理由（第二次回来的锚点） | 保持；入口文案改「我的审查档案」 |
| 评估系统（golden dataset） | 内部质量护栏 | 不对用户暴露；转化为对外「抽检一致率」指标（有真实数据后才展示） |

### 1.2 Demo 化/弱价值（收敛）

| 功能 | 问题 | 动作 |
| --- | --- | --- |
| Assistant 对话 | 与主任务弱相关，无明确入口策略 | 本轮不做新入口；不删除；待审查主链路数据验证后再决定 |
| 定价页微信渠道选择 | 商户资质未就绪，选择后无法完成支付 | 灰置标「即将开通」，避免假入口 |
| 首页技术参数叙事 | 对买家无决策价值 | 改业务语言（见 03 §2） |

### 1.3 缺失（必须补）

| 缺失 | 为什么重要 | 动作 |
| --- | --- | --- |
| 报告导出归档 | 审查任务的法定终点是归档留痕；没有导出=任务未完成 | P0：核对现有导出能力，缺失则补 docx 导出 |
| 转化漏斗埋点 | 无数据=商业化盲飞 | P0：事件表+关键埋点（见 07） |
| 公开定价页 | 游客看价是付费路径第一步 | P0 |
| 复用钩子 | 「为什么第二次回来」 | P1：报告完成后引导「继续审查下一份」+ 历史档案强化 |
| 真实案例页 | 政务买家看同行案例决策 | P1 结构先行，等真实客户填充 |

### 1.4 AI 任务完成能力专项检查（Agent 产品要求）

| 检查项 | 现状 | 结论 |
| --- | --- | --- |
| 工具调用稳定性 | 工具注册制+强校验（工程铁律） | ✔ 已达标 |
| RAG 检索质量 | pgvector+pg_trgm，BGE-M3 本地 | ✔；缺检索质量指标外显 |
| 来源引用 | EvidenceCard 条款级引用 | ✔ 差异化核心 |
| 幻觉控制 | Verifier+证据核验节点 | ✔；对外话术「结论不附依据则不显示」可承诺 |
| 任务执行日志 | agent_logs+Prometheus | ✔；缺用户侧「进度可视化」翻译 |
| 成本控制 | LLM Gateway 四层模型+JSON Mode | ✔；**缺单次审查成本统计**（单位经济必需，见 05） |
| 错误恢复 | retry edges+conditional routing | ✔ |
| 人工确认机制 | 报告页「人工复核」环节 + 免责声明 | ✔；合规底线，永远保留 |
| 失败替代流程 | SSE 中断 ErrorState 已有 | ◐ 需回归验证 429/超时文案 |

## 2. 路线图（按冲刺）

### Sprint C1「转化修复」（本周，P0 全部）
- 公开 /pricing（游客可见）
- 首页价格与后端同源、额度文案对齐（累计 2 次）
- 删除「支付接入中」过时横幅、微信渠道灰置
- 注册协议勾选
- 额度用尽升级弹层 UpgradeDialog
- 埋点最小集（见 07 §3）
- 验收：10 项 P0 验收清单全过 + CI 绿 + 支付链路回归

### Sprint C2「价值显性化」（下周，P1）
- 首页改造：业务语言重写+政策信任条+FAQ+证据演示区
- 报告导出（docx）+「继续下一份」复用钩子
- 定价页对比表与折算月价
- SEO 基础：sitemap/robots/OG + 2 个解决方案落地页（司法局版/起草单位版）
- 真实耗时/成本数字实测并回填首页话术

### Sprint C3「增长基建」（第 3-4 周）
- 内容页模板：功能专题/使用指南/比较页
- 案例页框架（等真实客户）
- A/B：定价页「年付默认 vs 月付默认」
- 邮件/站内激活序列：注册未首任务 24h 提醒（用站内通知，无需外部邮件服务）

### Sprint C4+「商业化深化」（第 2 个月起）
- 支付宝真实扣款验收收官（用户扫码，**阻塞中，运营方动作**）
- 微信支付商户资质办理后启用渠道
- 团队席位（企业版多人）与对公发票流程
- 私有化部署报价包（对标 Luminance 结构：部署费+年维保）
- 多租户隔离覆盖剩余路由（P3 但政务销售前必须补齐）

## 3. 明确不做的

- 不做通用法律问答（红海且偏离法定审查场景）
- 不做移动 App（用户在 PC 办公场景）
- 不做实时协作编辑（超出审查场景）
- 不在无真实数据前上线任何「客户见证」

## 4. 里程碑判定

| 里程碑 | 定义 |
| --- | --- |
| M-C1 | P0 清零，游客可走完「看价→注册→免费 2 次→被引导付费」全链路 |
| M-C2 | 首单真实付费成交（支付宝验收完成） |
| M-C3 | 5 个真实激活用户（完成≥1 次审查且≥1 次复访） |
| M-C4 | 首个付费县客户 + 可复用案例页 |
